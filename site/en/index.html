Find the infection. Understand the intrusion. Take back control.

An open-source WordPress malware investigation and incident response toolkit: find malware and persistence, verify core, plugin and theme integrity, and remediate under your control. For people who need to know what happened, not just see a green checkmark.

Install Facheiro Explore the docs Source on GitHub 
$ cd wp-content/plugins
$ git clone https://github.com/fcavallari/Facheiro.git facheiro
$ wp plugin activate facheiro

Open source, GPLv2 or later. No account and no telemetry. Not on WordPress.org yet, so it installs from GitHub.

From infection to recovery

Four stages, each one clear about what it touches on your site. Scanning and investigating never change anything. Remediating and hardening write only when you tell them to, and show you first what they will do.

  1. Scan

    Read-only: the admin, wp facheiro scanall, or a CLI without WordPress

    Seven checks in one report: the usual hiding places, core, plugin and theme integrity, the database, access logs, malware signatures, modification times and the crontab.

    From the admin it runs in the background through WP-Cron, so you can close the tab. Anything that blocks a check becomes an ERROR finding instead of being skipped.

  2. Investigate

    Read-only: the judgement is yours

    Read the findings worst first and follow the leads: files modified minutes after suspicious traffic, PHP with a back-dated timestamp, administrators created days ago.

    • Mark a false positive with a note. The mark holds only while the file is byte for byte the one you reviewed.
    • Download the sample as an encrypted zip, or look its hash up on VirusTotal.
    • Export the report as text or NDJSON, or ask an AI assistant to explain a finding.

  3. Remediate

    Writes files: from WP-CLI only, after a dry run

    Cleaning and restoring write to disk, so they stay out of the admin. Take a backup, preview with --dryrun, and only then run it for real.

    • Cleaned files are written to a temp file and renamed into place, so a failed write can't truncate the original.
    • Each file from the official zip is checked byte for byte against the checksums before it's written. A tampered package is refused.
    • --quarantine-dir keeps each original as evidence. Extra files are never deleted.
    $ wp facheiro scan --dryrun
    $ wp facheiro scan
    $ wp facheiro integrity --restore --dryrun
    $ wp facheiro integrity --restore --quarantine-dir=/path/outside/webroot

  4. Harden

    Writes only its own blocks, and undoes them if the site breaks

    Server rules that refuse PHP in uploads, copies of wp-config.php, hidden files, backups and logs, WordPress internals and folder listings.

    On Apache and LiteSpeed Facheiro writes only between # BEGIN Facheiro and # END Facheiro, checks the home page, the login and admin-ajax, and puts every file back as it was if any of them stops answering. On Nginx you download the file and include it.

One scan, from the admin

Open Facheiro in the admin menu and click Start scan. The filters below work as they do in the plugin: try them.

  • In the background

    The scan carries on through WP-Cron with the tab closed. If WP-Cron is unreliable on your host, it runs only while the page is open.

  • Worst first

    HIGH, MEDIUM, LOW, INFO and ERROR, with severity filters.

  • False positives with proof

    A mark stores the SHA-256 of the file or value you reviewed. If it changes, the finding comes back.

  • Samples and VirusTotal

    Download sample makes a zip with the password infected. The VirusTotal link carries only the hash and is opened by your browser.

  • Scheduled

    Daily, twice daily or weekly, in the site's timezone.

  • What one scan looks at

    Seven checks in one report. Anything that blocks one of them, like an unreadable file or a missing PHP extension, is reported as an error instead of skipped.

  • The usual hiding places

    Executable PHP in uploads, auto_prepend_file in .user.ini, php.ini and .htaccess, mu-plugins and hidden PHP.

    UPLOADS_PHP PHP_PREPEND MU_PLUGIN HIDDEN_PHP

  • Integrity

    Core, every plugin and every theme against the official wordpress.org package for the installed version. What can't be checked is reported as such.

    INTEGRITY_MODIFIED INTEGRITY_MISSING INTEGRITY_EXTRA

  • Database

    Read-only. Recent administrators, roles with admin powers, PHP, iframes and obfuscated JavaScript in options and posts, a hijacked siteurl and tampered active_plugins.

    DB_NEW_ADMIN DB_ROLE_CAPS DB_OPTION_IOC DB_POST_IOC

  • Access logs

    Webshell requests, exploits of known plugins, .env probes, brute force, and the files changed minutes later. Reads .gz and rotated logs.

    LOG_IOC LOG_FILE_CORRELATION

  • Malware signatures

    Known injections such as the ndsw/ndsx and wqpq campaigns, generic webshells, and the signatures you write. From the admin, a dry run only.

    MALWARE_FOUND SIGNATURE_MATCH

  • Modification times

    Files changed after the rest of their package, and PHP whose time was pushed back with touch. Leads, not proof.

    TIMESTAMP_OUTLIER TIMESTAMP_TIMESTOMP

  • Crontab

    The crontab of the user PHP runs as, checked for piped base64 decoders, pastebin downloads and droppers in tmp folders. The persistence that survives a file cleanup.

    CRONTAB_IOC

Built for compromised environments

Security tools should never make an incident worse.

Facheiro runs on a server that may be in someone else's hands. So it treats every filename, log line, database value and API response as hostile, and keeps what only reads clearly apart from what writes.

What only reads

  • Scans change nothing

    Scans from the admin, recovery mode and AI assistants only report.

  • The database is only read

    SELECT queries only, wp-config.php is read without being executed, and stored values are never unserialized, which could trigger PHP object injection.

  • Nothing leaves the server

    No account and no telemetry. The only outbound requests go to wordpress.org, for checksums and official packages.

  • TLS verification stays on

    An "all clean" answer must never come from an attacker sitting between the site and wordpress.org.

  • Blocked checks are loud

    A missing extension, an unreachable database or an unreadable log is an ERROR finding. A clean report means every scanner actually looked.

  • Facheiro checks itself

    Every scan starts by verifying the plugin's own files against the official checksums, or the list shipped with it.

  • Assistants look, never touch

    No AI tool cleans, restores or writes files. Everything scanned is labelled as untrusted data, so a planted file can't give the assistant orders.

What writes, and how it guards you

  • Cleanup and restore from WP-CLI only

    Never from the admin. With --dryrun to preview first, and writes to a temp file renamed into place.

  • Restores are verified first

    Each file from the official zip is checked byte for byte against the reference checksums before it's written. A tampered package is refused, and extra files are never deleted.

  • Hardening undoes itself

    After writing rules, Facheiro loads the home page, the login and an admin request. If any of them breaks, every file goes back exactly as it was.

  • A false positive can't hide a changed file

    A mark on a file stores its SHA-256. If the file changes, the finding comes back.

  • Sealed settings

    False positives, signatures and settings are sealed. A change made straight in the database, the way an attacker would hide a backdoor, shows up in the next scan.

  • The admin writes only what you ask for

    The only files it ever writes are the .htaccess rules you apply and the recovery key you create.

A clean scan is not proof of a clean site. The signatures find known malware, integrity covers only packages that exist on wordpress.org, and timestamps and logs are leads, not proof. An attacker who can write files can also rewrite the seal: this is detection, not prevention. Treat the report as the start of the investigation.

For deeper investigations

Every scanner is a wp facheiro command, with text or NDJSON output you can pipe. The same engine runs without WordPress, on a recovery page and for AI assistants.

Investigate

wp facheiro scanall
Every check, findings worst first.
wp facheiro quick
Uploads, prepend, mu-plugins and hidden PHP.
wp facheiro integrity
Core, plugins and themes against wordpress.org.
wp facheiro db
Administrators, options, siteurl/home, active_plugins and posts. Read-only.
wp facheiro log <path> --correlate
The access log, and the files changed around the attack.
wp facheiro times
Times out of step with the package. Leads only.
wp facheiro cron
The crontab of the user PHP runs as.

Remediate

wp facheiro scan --dryrun
Previews the signature cleanup. Without --dryrun, it cleans.
wp facheiro integrity --restore --dryrun
Previews the restore from the official packages.

Harden and maintain

wp facheiro harden --check
Tests what the server actually refuses, without creating anything on the site.
wp facheiro recovery-key create --expires=7
Creates the recovery mode key.
wp facheiro selfcheck
Verifies Facheiro's own files and the settings seal.
wp facheiro seal status
Shows what changed outside Facheiro.

When WordPress won't load

Recovery mode is a key-protected page that works after a white screen or a critical error. It shows the PHP errors that broke the site and the plugin or theme they point at, and runs the full scan. Without a key it answers 404.

Or run the same scanners from the plugin folder with the standalone CLI. It needs PHP 5.6 and no working WordPress.

$ php bin/facheiro.php scanall=1 scandirectory=/path/to/wp-root
$ php bin/facheiro.php help=1

AI assistants over MCP

On WordPress 6.9 or newer with the MCP Adapter plugin, Claude, ChatGPT, Antigravity or Cursor use these abilities, for administrators only:

  • start-scan
  • advance-scan
  • cancel-scan
  • get-status
  • list-findings
  • get-finding
  • read-flagged-file
  • mark-false-positive
  • unmark-false-positive
  • list-false-positives
  • list-signatures
  • test-signature
  • save-signature
  • delete-signature

None of them cleans, restores or writes site files, and everything read from the site is labelled as untrusted data. No MCP? Copy a ready-made summary into any chat.

Custom signatures

Exact text or regular expressions for files, options or posts. Test one against a sample, export it as JSON, and use the same list in the admin, with assistants and on the command line.

{"id": "acme-loader", "target": "file", "severity": "HIGH",
 "match": [{"string": "acme_loader"},
           {"regex": "/file_put_contents\\s*\\([^;]{0,100}\\.php['\"]\\s*,/i"}]}

Custom signatures only detect: no rule anyone writes can change or delete a file. Writing signatures

Text

One line per finding, the same shape from every scanner. Paths and log content come from the compromised host, so control characters and commas in paths are percent-encoded. A crafted filename can't forge a finding line.

SEVERITY,TYPE,path,detail

JSON

--format=json prints one event per line on stdout and sends progress to stderr. The admin's JSON export uses the same events.

{"event":"finding","severity":"HIGH",
 "type":"LOG_IOC","path":"...","detail":"..."}

What the exit code tells you

  1. 0

    Clean, or informational findings only.

  2. 1

    Usage or fatal error. Check the arguments.

  3. 2

    LOW, MEDIUM or ERROR findings to review.

  4. 3

    HIGH findings. A successful cleanup exits 3 too: malware was found.

Install it

Facheiro isn't on WordPress.org yet, so install it from GitHub.

Get the plugin

$ cd wp-content/plugins
$ git clone https://github.com/fcavallari/Facheiro.git facheiro
$ wp plugin activate facheiro

Or download the repository as a zip and unpack it as wp-content/plugins/facheiro/. The folder has to be named facheiro.

First scan

  1. Open Facheiro in the admin menu, or the Network Admin on multisite, and click Start scan.
  2. Under Settings, add the location of the access logs and, if you want, automatic scans.
  3. Apply the Recommended template on the Hardening tab.
  4. Create a recovery key on the Recovery tab, so recovery mode is ready if the site ever breaks.
  5. Take a backup, then clean up with the WP-CLI commands shown under the results.

Requirements

  • WordPress 6.0 or newer and PHP 7.2 or newer. The standalone CLI and recovery mode run on PHP 5.6.
  • Shell access only to clean or restore files. The admin pages need none.
  • WordPress 6.9 and the MCP Adapter plugin for AI assistants.
  • Apache or LiteSpeed with AllowOverride for the hardening rules Facheiro writes. On Nginx, someone with server access includes the generated file.
  • Some checks use PHP extensions that locked-down hosts lack: zlib for .gz logs, zip for themes and every restore, shell_exec for the crontab. A missing one is reported as an ERROR.

Take a backup before cleaning. Preview with --dryrun.

It finds known malware. A clean scan is not proof of a clean site, and log hits include plenty of attempts that failed.

Send what it missed

Facheiro only knows malware someone has already caught. If you clean a site and find something it didn't flag, open a GitHub issue with a sample so the next scan catches it.

Put this in the issue

  • The sample. Download sample on the finding gives you a zip encrypted with the password infected, with a manifest of where and why it was flagged. GitHub won't take a bare .php attachment.
  • Its SHA-256 hash, and the path where you found it.
  • How it was loaded: an include in functions.php, an mu-plugin, a cron entry, auto_prepend_file, or something else.
  • The WordPress, plugin and theme versions, if you have them.
  • For attack traffic, the matching access log lines.
  • If you wrote a signature that catches it, export it from the Signatures tab and attach the JSON.

Package it from a shell

$ shasum -a 256 suspicious.php
$ zip -j -P infected sample.zip suspicious.php

Issues are public. Remove anything that identifies the site before you upload.

That means domain names, database credentials, salts, email addresses and visitor IPs in log lines. Never attach wp-config.php or a database dump.

The facheiro is a cactus of the Brazilian caatinga. Without its thorns it is water and feed when nothing else is left. The plugin does the same for a hacked site: it takes away what hurts and leaves what is useful.
